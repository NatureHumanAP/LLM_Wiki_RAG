# /query — LLM Wiki 질의 스킬

`wiki/` 문서를 기반으로 질문에 답변한다.
벡터 검색 없이 index.md → 관련 페이지 순서로 탐색한다.

인자 예시: `/query MCP가 뭐야?` `/query MLOps 아키텍처 설명해줘`

---

## Step 0. 질문 확인

`$ARGUMENTS`가 있으면 그것이 질문이다.
없으면 사용자에게 질문을 요청한다.

---

## Step 1. 인덱스 로드

`wiki/index.md`를 읽는다. 스킵하지 않는다.

질문의 키워드와 인덱스 항목을 대조해 관련 페이지 후보 목록을 만든다.
관련성이 있을 수 있는 페이지는 모두 포함한다 (과소 선택보다 과다 선택 우선).

---

## Step 2. 관련 페이지 읽기

후보 목록의 페이지를 읽는다. 우선순위:

1. `wiki/concepts/` — 개념 정의·구조·활용
2. `wiki/summaries/` — 특정 소스의 사실 확인이 필요할 때
3. `wiki/entities/` — 특정 도구·사람·서비스 정보
4. `wiki/comparisons/`, `wiki/syntheses/` — 비교·종합 페이지

`raw/`는 절대 먼저 읽지 않는다. wiki 페이지로 커버 안 될 때만 마지막 수단으로 참조한다.

---

## Step 3. 답변 생성

다음 형식으로 답변한다.

### 답변 형식

```
[질문에 대한 직접 답변]

**근거 페이지**: [[페이지명]], [[페이지명]], ...
```

규칙:
- 답변 내 wiki 내부 참조는 `[[wikilink]]` 형식으로 표시한다
- 사실(소스 기반)과 해석(AI 연결)을 구분해서 쓴다
  - 사실: "[[summary-xxx]]에 따르면 ..."
  - 해석: "이를 연결하면 ..."
- wiki에 없는 내용은 "wiki에 아직 없음"으로 명시하고 추가 소스 수집을 제안한다
- 모순이 발견되면 `⚠️ 모순:` 으로 명시하고 양쪽 소스를 모두 인용한다

---

## Step 4. 저장 여부 판단

답변이 다음 중 하나에 해당하면 저장을 제안한다.

저장 가치 있는 답변:
- 여러 wiki 페이지를 연결한 비교·분석
- 새로운 연결고리 발견 (기존 페이지에 없던 인사이트)
- 반복적으로 물어볼 가능성이 높은 질문
- 포트폴리오·취업에 직접 활용 가능한 정리

저장 가치 없는 답변 (저장 제안 생략):
- 단순 사실 조회 (이미 wiki에 있는 내용 그대로 반환)
- 일회성 확인

저장 제안 형식:
```
이 답변을 wiki에 저장할까요?
저장 시: wiki/[타입]/[파일명].md 생성 예정
```

저장 승인 시 → 해당 타입의 wiki 페이지를 생성하고 index.md와 log.md를 업데이트한다.

---

## 절대 규칙

- `raw/` 파일은 마지막 수단 — wiki 먼저
- 답변에 출처 표시 필수 (`[[wikilink]]`)
- wiki에 없는 내용을 있는 것처럼 지어내지 않는다
- 사실과 해석을 섞지 않는다
