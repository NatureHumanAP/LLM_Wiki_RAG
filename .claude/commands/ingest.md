# /ingest — LLM Wiki 인제스트 스킬

`raw/` 폴더의 새 파일을 감지해 wiki로 컴파일한다.
인자로 파일 경로를 지정하면 해당 파일만 처리한다. 예: `/ingest raw/youtube/파일명.md`

---

## Step 0. 인자 처리

`$ARGUMENTS`가 있으면 해당 경로의 파일을 직접 대상으로 설정하고 Step 2를 건너뛴다.
없으면 Step 1부터 순서대로 진행한다.

---

## Step 1. 컨텍스트 로드

다음 파일을 순서대로 읽는다. 스킵하지 않는다.

1. `CLAUDE.md` — 볼트 운영 규칙 전체 확인
2. `wiki/log.md` — 이미 인제스트된 파일 목록 파악
3. `wiki/index.md` — 현재 wiki 상태 파악

---

## Step 2. 새 파일 탐지 (인자 없을 때)

`raw/` 하위 전체를 재귀 스캔해 `.md` 파일 목록을 수집한다.
다음 파일은 제외한다:
- `CLAUDE.md`
- `_about.md`

`wiki/log.md`에 파일명이 언급된 파일 = 이미 인제스트됨. 나머지 = 새 파일.

- 새 파일이 **1개**: 바로 진행
- 새 파일이 **여러 개**: 목록을 보여주고 사용자에게 선택 요청
- 새 파일이 **없음**: "인제스트할 새 파일이 없습니다" 알리고 종료

---

## Step 3. 소스 파일 읽기

대상 파일을 읽는다. **절대 수정하지 않는다.**

frontmatter의 `raw_type` 값에 따라 분석 방향을 다르게 한다:

| raw_type | 분석 우선순위 |
|----------|--------------|
| `youtube` | transcript 섹션 전체, 타임스탬프 구조, 영상 설명 |
| `article` | 본문 흐름, 주요 섹션 헤딩, 핵심 문단 |
| `book` | 챕터 구조, 핵심 인용문, 저자 주장 |
| `podcast` | 에피소드 노트, 설명, 주요 발언 |
| `research` | 초록, 방법론, 핵심 발견, 결론 |
| `notes` 또는 없음 | 자유 형식, 전체 맥락 우선 |

---

## Step 4. 소스 분석 보고

사용자에게 다음 형식으로 보고한다.

```
파일: [파일명]
raw_type: [타입] | 출처: [채널/저자/URL] | 게시: [날짜]
```

### 핵심 주장 (Key Claims)
번호 목록. **사실만** 기록하고 해석은 쓰지 않는다.
스폰서·광고 섹션이 있으면 별도로 표시한다.

### 언급된 엔티티
표 형식: `엔티티명 | 분류(사람/도구/조직/서비스/라이브러리) | 역할`
이미 wiki에 있는 엔티티는 `[[wikilink]]`로 표시한다.

### 다루는 개념
목록 형식. 이미 wiki에 있는 개념은 `[[wikilink]]`로 표시한다.

---

## Step 5. 사용자에게 3가지 질문

분석 보고 직후 아래 질문을 한다. 사용자 답변을 기다린다.

> **Q1.** 이 파일을 왜 저장했어?
> *(수집 목적, 무엇이 끌렸는지)*
>
> **Q2.** 지금 하고 있는 일과 어떻게 연결돼?
>
> **Q3.** 이걸로 뭘 해보고 싶어?

---

## Step 6. wiki 페이지 생성/업데이트

사용자 답변을 받은 후 실행한다. 사용자 답변의 맥락을 개념·종합 페이지에 반영한다.

### 6-1. 소스 요약 페이지 (항상 생성)

경로: `wiki/summaries/summary-[제목약칭]-[연도].md`

```yaml
---
title: "요약 — [소스 제목]"
type: summary
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "[raw 파일 경로]"
source_count: 1
---
```

내용 구성:
- `## 소스 정보` — URL, 출처, 게시일, 형식, 주의사항(광고 등)
- `## 핵심 주장` — 사실만. 번호 목록
- `## 언급된 엔티티` — 표 형식, wikilink 포함
- `## 다루는 개념` — 목록, wikilink 포함

### 6-2. 엔티티 페이지

경로: `wiki/entities/entity-[영문명].md`

- 이미 있으면: 새 소스 추가, `source_count` 증가, 관련 정보 보강
- 없으면: 새로 생성
- 단 한 줄 스쳐 지나간 언급이면 생략 가능 (향후 소스가 쌓이면 생성)

```yaml
---
title: "[엔티티명]"
type: entity
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: []
source_count: 0
---
```

### 6-3. 개념 페이지

경로: `wiki/concepts/concept-[영문명].md`

- 이미 있으면: 새 소스·관점 추가, `source_count` 증가, 사용자 맥락 반영
- 없으면: 새로 생성
- **사용자의 Q1·Q2·Q3 답변에서 얻은 맥락(왜 중요한지, 어떻게 쓸지, 다음 단계)을 반영**

```yaml
---
title: "[개념명]"
type: concept
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: []
source_count: 0
---
```

내용 구성 (해당되는 것만):
- `## 정의`
- `## 왜 필요한가`
- `## 구조 / 동작 방식`
- `## 실무 활용`
- `## AX 개발자와의 연관성` ← 해당될 때만
- `## 학습 로드맵` ← 사용자 Q3 답변 반영
- `## 관련 개념` / `## 소스`

### 6-4. 크로스링크 점검

생성/업데이트한 페이지들이 서로, 그리고 기존 wiki 페이지들과 적절히 `[[wikilink]]`로 연결됐는지 확인한다.
두 소스에 공통으로 등장하는 엔티티·개념이 있으면 양쪽 페이지에 상호 링크를 추가한다.

---

## Step 7. index.md 업데이트

`wiki/index.md`를 열어 새 페이지를 해당 섹션에 추가한다.

- `## Sources` → 요약 페이지
- `## Entities` → 새 엔티티 (기존 업데이트면 생략)
- `## Concepts` → 새 개념 (기존 업데이트면 생략)

항목 형식: `- [[페이지명]] — 한 줄 요약` (120자 이내, 한 줄)

---

## Step 8. log.md 업데이트

`wiki/log.md`에 맨 앞(기존 항목 위)에 추가한다. 형식:

```
## [YYYY-MM-DD] ingest | [소스 제목]

소스: `[raw 파일 경로]`
[raw_type] | 게시: [날짜] | 출처: [채널/저자]

수집 맥락 (사용자 제공):
- 목적: [Q1 요약]
- 연결: [Q2 요약]
- 다음 단계: [Q3 요약]

생성된 페이지:
- [CREATE/UPDATE] `wiki/summaries/...`
- [CREATE/UPDATE] `wiki/concepts/...`
- [CREATE/UPDATE] `wiki/entities/...`
- UPDATE `wiki/index.md`

크로스링크: [연결된 기존 페이지들]
```

---

## 절대 규칙

- `raw/` 파일은 **절대 수정하지 않는다**
- 소스 요약 섹션에는 **사실만** 기록 (해석 금지)
- 모든 wiki 페이지에 **YAML frontmatter** 포함
- 내부 참조는 **`[[wikilink]]`** 형식
- `index.md` 항목은 **한 줄, 120자 이내**
- `log.md`는 **append-only** (기존 항목 수정 금지)
- 새 페이지 생성보다 **기존 페이지 업데이트 우선**
