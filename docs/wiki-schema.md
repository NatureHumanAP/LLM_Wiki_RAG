# LLM Wiki 운영 스키마

평가 대상 코퍼스(`wiki/`)를 만들고 유지하는 규칙. 원본은 개인 지식베이스의 `CLAUDE.md`이며, 개인 정보 섹션은 제외하고 구조·운영 규칙만 옮겼다.

---

## 볼트 구조

```
llm-wiki/
├── CLAUDE.md          ← 이 파일. 스키마 + 운영 규칙
├── raw/               ← 불변 원본 인풋 (절대 수정 금지)
│   ├── article/       ← 웹 아티클, 기술 블로그
│   ├── youtube/       ← YouTube 영상 스크립트
│   ├── podcast/       ← 팟캐스트 에피소드
│   ├── book/          ← 책 노트
│   ├── research/      ← 논문, 연구 자료
│   ├── notes/         ← 단발성 직접 메모 (아이디어, 개발 기록, 취업 노트)
│   └── projects/      ← 프로젝트별 지속 기록 (하위 폴더로 구분)
├── wiki/              ← AI가 컴파일·유지하는 위키 (AI 소유)
│   ├── index.md       ← 전체 목차 (항상 최신 유지)
│   ├── log.md         ← 오퍼레이션 로그 (append-only)
│   └── [pages]        ← AI가 생성·관리하는 페이지들
└── output/            ← 외부용 결과물
    ├── resume/        ← 이력서·포트폴리오
    └── snippets/      ← 재사용 코드 스니펫
```

---

## 핵심 원칙

- `raw/`는 **소스 오브 트루스** — AI는 읽기만 하고 절대 수정하지 않는다
- `wiki/`는 **AI 소유** — AI가 생성하고 유지한다. 사람은 읽는다
- wiki는 **누적되는 아티팩트** — 질문할 때마다 재발견하지 않는다. 한 번 컴파일하고 계속 업데이트한다
- **좋은 쿼리 답변은 wiki 페이지가 된다** — 채팅 히스토리에 사라지지 않는다

---

## 오퍼레이션

### 1. Ingest (소스 추가)
새 raw 파일을 추가하고 AI에게 처리를 요청할 때의 흐름:

1. `raw/[폴더]/` 에 파일 추가
2. AI가 파일을 읽고 핵심 내용을 나와 논의
3. AI가 `wiki/`에 요약 페이지 작성
4. AI가 관련 entity·concept 페이지 업데이트 (하나의 소스가 10-15개 페이지에 영향 가능)
5. AI가 `wiki/index.md` 업데이트
6. AI가 `wiki/log.md`에 항목 추가

**명령 예시**: "raw/learning/에 넣은 파일 인제스트해줘"

### 2. Query (질의)
wiki를 기반으로 질문할 때의 흐름:

1. AI가 `wiki/index.md`를 먼저 읽어 관련 페이지 파악
2. 관련 `wiki/` 페이지 읽기
3. 필요시에만 `raw/` 원본 참조 (마지막 수단)
4. 답변 생성 + 인용 포함
5. **가치 있는 답변은 wiki 페이지로 저장** (비교표, 분석, 발견한 연결고리 등)

**명령 예시**: "React와 Vue를 비교해줘" → 답변 후 → "이거 wiki에 저장해줘"

### 3. Lint (위키 건강검진)
주기적으로 wiki 상태를 점검:

- 페이지 간 모순 탐지
- 최신 소스로 갱신된 stale 클레임 확인
- 인바운드 링크 없는 고아 페이지 탐지
- 언급은 됐지만 페이지가 없는 중요 개념
- 누락된 cross-reference
- 웹 검색으로 보완 가능한 데이터 갭

**명령 예시**: "wiki lint 해줘"

## Wiki 페이지 타입

| 타입 | 용도 | 파일명 예시 |
|------|------|-------------|
| **Summary** | raw 소스 하나의 요약 | `[날짜]-[제목]-summary.md` |
| **Entity** | 사람, 기술, 도구, 회사 | `entity-React.md` |
| **Concept** | 개념, 패턴, 기법 | `concept-MVC패턴.md` |
| **Comparison** | 둘 이상의 비교 | `comparison-React-vs-Vue.md` |
| **Synthesis** | 여러 소스를 아우르는 종합 | `synthesis-프론트엔드-현황.md` |
| **Overview** | 특정 도메인 전체 조망 | `overview-웹개발.md` |

## Wiki 운영 규칙 (절대 준수)

| 규칙 | 내용 |
|------|------|
| raw/ 불변 | `raw/` 내 기존 파일 절대 수정 금지. 추가만 가능 |
| index 동기화 | 페이지 생성·삭제 시 `index.md` 필수 업데이트 |
| 로그 기록 | 모든 오퍼레이션마다 `log.md`에 기록 |
| wikilink | 내부 참조는 `[[페이지명]]` 형식 |
| frontmatter | 모든 wiki 페이지에 YAML frontmatter 필수 |
| 모순 처리 | 모순 발견 시 양쪽 소스 모두 인용 + `⚠️ 모순` 태그 |
| 사실/해석 분리 | 소스 요약 섹션 = 사실만. 해석은 Concept/Synthesis 페이지에서 |
| 탐색 순서 | `index.md` → `wiki/` 페이지 → `raw/` (마지막 수단) |
| 업데이트 우선 | 새 페이지 생성보다 기존 페이지 업데이트 우선 |
| index 형식 | index 항목은 한 줄, 120자 이내 |
| 답변 환류 | 가치 있는 쿼리 답변은 wiki 페이지로 저장 |
